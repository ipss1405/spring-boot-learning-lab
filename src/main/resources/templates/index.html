Properties vs YAML

                    
Properties y YAML cumplen la misma función: permiten configurar aspectos de la aplicación como el puerto, la conexión a la base de datos y opciones de JPA. La diferencia principal está en la forma de escribir la configuración: application.properties utiliza claves separadas por puntos, mientras que application.yml organiza la información de forma jerárquica mediante indentación.

                    Validaciones
Detén datos incorrectos antes del Service

                    
Las validaciones impiden que datos incorrectos lleguen a la lógica del sistema: @NotBlank evita texto vacío, @Email comprueba el correo y @Min(1) exige un mínimo. @Valid activa estas validaciones cuando el Controller recibe la petición.

                    
Ver DTO y uso de @Valid
public record PrestamoRequest(
    @NotBlank String nombreAlumno,
    @NotBlank @Email String correoAlumno,
    @NotNull @Min(1) Long recursoId
) {}

// En el Controller:
registrar(@Valid @RequestBody PrestamoRequest request)
@NotNull exige un valor; @Min(1) exige que sea al menos 1. @Email comprueba el formato y @NotBlank impide cadenas vacías.

                    

                        
                        
                        
                        
                    

                    
Simulación educativa local. No registra préstamos ni cambia PrestamoRequest: @Min(1) se enseña aquí como ejemplo; la validación definitiva corresponde al backend.

                    Java Records
    Un DTO con menos código repetitivo
    
                    
    Una clase tradicional necesita campos, constructor y accesores. Un Record expresa los datos de forma compacta: Java genera automáticamente constructor, accesores, equals, hashCode y toString.
    
                    
                    
    Problema y solución
    Problema: DTO tradicional
    Solución con Record
    Comparación ilustrativa de DTOs, sin sustituir PrestamoResponse real. La clase mostrada incluye campos, constructor y accesores; el Record también genera equals, hashCode y toString.
    
                
    

                        
    
                    Virtual Threads
    Atender muchas solicitudes que esperan I/O
    
                    
    Un hilo tradicional puede quedar ocupado mientras espera una operación de entrada/salida. Un Virtual Thread normalmente permite liberar su hilo portador mientras espera I/O compatible.
    
                    
    HILO TRADICIONAL
    1. Solicitud
    2. espera BD / HTTP / archivo
    3. el hilo de plataforma permanece ocupado durante la espera
    VIRTUAL THREAD
    1. Solicitud
    2. espera BD / HTTP / archivo
    3. la JVM puede aprovechar el hilo de plataforma para atender otra tarea
    
                    
    Los Virtual Threads son útiles cuando una aplicación maneja muchas tareas concurrentes que pasan tiempo esperando operaciones de entrada/salida. No hacen que una operación individual sea más rápida ni están pensados principalmente para acelerar cálculos intensivos de CPU.
    
                    
                    
    Resultado de la simulación
    Listo para simular tres solicitudes.
      Los Virtual Threads son livianos y permiten manejar muchas tareas bloqueantes con menor costo.
      
                    
      Modelo educativo, no un benchmark. En Java 21 algunas operaciones pueden fijar un Virtual Thread a su portador. No reemplazan mágicamente el rendimiento de tareas intensivas de CPU.
      
                    
      Ver la propiedad de configuración
      spring.threads.virtual.enabled=true
      Ya existe en el proyecto; esta actividad no la modifica.

      ¿Cómo leer y probar Swagger?
      
                        
        
                            
      • GET → consulta información y no crea registros.
        • 
                            
      • POST → crea un nuevo recurso. En este proyecto permite registrar un préstamo.
        • 
                            
      • PATCH → modifica parcialmente un recurso existente. En este proyecto permite registrar la devolución de un préstamo.
        • 
                            
      • Try it out → habilita el endpoint para realizar una prueba.
        • 
                            
      • Execute → envía realmente la petición HTTP al backend.
        • 
                            
      • Request body → datos JSON que enviamos.
        • 
                            
      • Response body → datos JSON que devuelve Spring Boot.
        • 
                        
      
                        
      Códigos HTTP: ¿qué significa la respuesta?
        
                            
      • 200 OK → operación realizada correctamente.
        • 
                            
      • 201 Created → nuevo registro creado.
        • 
                            
      • 400 Bad Request → los datos enviados tienen errores.
        • 
                            
      • 404 Not Found → el recurso solicitado no existe.
        • 
                            
      • 409 Conflict → la operación entra en conflicto con el estado actual del recurso.
        • 
                        
      
                        
      Swagger UI → Controller → Service → Repository → H2
      
                    
      
                    
      GET es seguro para practicar porque solo consulta información. POST y PATCH ejecutan operaciones reales y pueden modificar los datos almacenados en H2.

      DTO · validación de datos
      
                    
      Construye un DTO sencillo
      
                    
      Necesitamos recibir nombre, correo e identificador del recurso para registrar un préstamo. Sustituye los espacios en blanco por @NotBlank, @Email y @Min(1), según corresponda.
      
                    
                    
                    
      Comprobación educativa de texto: no compila ni ejecuta Java. Este DTO de práctica no cambia las validaciones reales del backend.
      
                    
                    
      
                    
      Comparar con solución
      public record PrestamoRequest(
    @NotBlank
    String nombreAlumno,
    @Email
    String correoAlumno,
    @Min(1)
    Long recursoId
) {}
      @NotBlank rechaza un nombre nulo, vacío o formado solo por espacios. @Email comprueba el formato del correo. @Min(1) exige un identificador de al menos 1 cuando hay valor. @Email y @Min no rechazan null por sí solas; para exigir presencia se necesitan restricciones adicionales. @Valid activa la validación del DTO recibido por un Controller.

      Detalle técnico de la consulta
      
                    
      ¿Cómo leer esta tabla?
      
                        
      Tabla
      Conjunto de datos relacionados; PRESTAMO reúne los préstamos.
      
                        
      Columna
      Una característica, como NOMBRE_ALUMNO o ESTADO.
      
                        
      Fila / registro
      Un préstamo almacenado, con sus propios datos.
      
                        
      ID
      Identificador único de un registro.
      
                        
      Clave primaria
      Campo que distingue cada registro. En PRESTAMO es ID, declarado con @Id y generado automáticamente.
      
                    
      
                    
      Ver estructura
                        
      Estructura real verificada en H2 y en las entidades del proyecto. Los nombres SQL usan mayúsculas; los atributos Java, camelCase.
      
                        
      
                            
      PRESTAMO · Entity Prestamo
      
                                
      ID · BIGINT
      id · clave primaria, @GeneratedValue(IDENTITY).
      
                                
      NOMBRE_ALUMNO · CHARACTER VARYING
      nombreAlumno · nombre del estudiante.
      
                                
      CORREO_ALUMNO · CHARACTER VARYING
      correoAlumno · correo del estudiante.
      
                                
      FECHA_PRESTAMO · TIMESTAMP
      fechaPrestamo · fecha y hora de creación.
      
                                
      ESTADO · CHARACTER VARYING
      estado · estado del préstamo.
      
                                
      RECURSO_ID · BIGINT
      recurso · relación @ManyToOne con RECURSO.ID.
      
                            
      
                            
      RECURSO · Entity Recurso
      
                                
      ID · BIGINT
      id · clave primaria generada.
      
                                
      NOMBRE · CHARACTER VARYING
      nombre · nombre del libro o equipo.
      
                                
      TIPO · CHARACTER VARYING
      tipo · categoría del recurso.
      
                                
      DISPONIBLE · BOOLEAN
      disponible · indica si puede prestarse.
      
                            
      El DTO de respuesta expone recursoId, recurso y tipoRecurso; el nombre y el tipo provienen de RECURSO, no son columnas de PRESTAMO.
      
                        
      
                    
      
                
      
                
      
                    
      ¿Qué hace JPA/Hibernate?
      Explicación educativa
      
                    
      En Java trabajamos con objetos como Prestamo. JPA define cómo relacionarlos con la base de datos y Hibernate realiza gran parte de ese trabajo automáticamente.
      
                    
      Objeto Java: Prestamo→JPA / Hibernate→Fila en H2: PRESTAMO
      
                    
      Ver ejemplo SQL
                        
      Ejemplo representativo · no ejecutado ni capturado en tiempo real
      
                        
      SELECT ID, NOMBRE_ALUMNO, CORREO_ALUMNO,
       RECURSO_ID, ESTADO, FECHA_PRESTAMO
FROM PRESTAMO
ORDER BY ID;
      
                        
      JPA/Hibernate puede generar instrucciones SQL para comunicarse con la base de datos. Este SELECT corresponde al esquema real y sirve para entender cómo se leen registros; la visualización de arriba consulta el endpoint existente.
      
                    
      
                    
      Inspeccionar con H2 Console
                        
      La consola H2 es una herramienta técnica que permite inspeccionar directamente las tablas y ejecutar consultas SQL.
      
                        
      Ya está habilitada en este proyecto. Para inspeccionar utiliza consultas de lectura como SELECT; esta página de apoyo no ejecuta SQL ni cambia información.
